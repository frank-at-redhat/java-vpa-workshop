= Workshop Instructor Guide

This page is for the instructor who runs a delivery of the workshop.

== What the Workshop Covers

The audience is mixed: platform engineers who own the cluster and Java
developers who own the apps.
Attendees should be comfortable with `oc`, Deployments and resource requests
and limits; no prior VPA or OpenTelemetry experience is needed.
Afterwards they can set JVM flags that cooperate with the kubelet, inject the
OpenTelemetry Java agent without rebuilding an image, read a VPA
recommendation against JVM metrics, and pick a VPA update mode and resize
policy per workload.

== Delivery Notes

=== Timing

The 2-hour agenda on the xref:java-vpa:index.adoc[workshop page] is tight.
Spend the first 10 minutes getting the group's actual symptoms on the table;
the rest of the session refers back to them.
Module 2 (OpenTelemetry) is the one most likely to run long because the
Operator and Collector rollouts take real time.
Deploy the Collector during the Module 1 discussion if you need to buy time.

=== The recommender needs history

The VPA recommender gives you Operator minimums, not a recommendation, for the
first several minutes.
Create the `Off`-mode VPA in Module 3 as early as you can, start load, and
move on to the discussion while it accumulates samples.
Check `RecommendationProvided` in the VPA's conditions before showing numbers.

=== The two defaults that make VPA look broken

* `minReplicas` on the `VerticalPodAutoscalerController` defaults to 2, so a
one-replica Deployment is never touched in any mode but `Off`. The setup
requirements patch it to 1; say why, because attendees will hit this on their
own clusters.
* `podMinMemoryMb` defaults to 250, so recommendations never go below 250 Mi
no matter how little the app uses.

=== The updater's 12-hour rule

The VPA updater acts within a minute or two only when a pod's request is
outside the recommendation's bounds (Module 4, Exercise 2 relies on this: the
Module 1 sizing is far below the lower bound).
A pod that is inside the bounds isn't touched until it's 12 hours old.
After any rollout, the admission controller sizes the new pod at the target,
which puts it inside the bounds, so the updater goes quiet.
Module 4, Exercise 4 drives the resize by hand with the `resize` subresource
for that reason; use the same trick anywhere the updater is slower than the
room.

=== Put VPA Watch on the projector

Module 3 has attendees deploy a small live page in their own project (VPA
Watch, in `downloads/`).
Deploy one in your own project before the session and leave it on the
shared screen from Module 3 on: every resize, restart and recommendation
change in Module 4 shows up on it within ten seconds, with an event marker,
so you can narrate from the chart instead of from `watch` output.
It also lets you see at a glance whether the room is ahead of or behind
you.

=== Module 4 is the point of the workshop

If time is short, cut Exercise 2 of Module 1 and the `oc` metric queries in
Module 2 (use the console instead), but don't cut Module 4's Exercise 3.
Watching a memory resize land while `maxHeap` stays the same is the thing
attendees remember.

=== Common mistakes

* Putting the `inject-java` annotation on the Deployment's metadata instead of
the pod template. Nothing happens; look at the pod's YAML for the init
container.
* `JAVA_TOOL_OPTIONS` set in the image's `ENTRYPOINT`. The Operator's
`-javaagent` value replaces it and `MaxRAMPercentage` disappears. Set JVM
flags in the pod spec.
* Running the `curl` checks against a pod that is mid-resize or mid-restart.
Wait for `oc get pod` to show `Running` and `1/1` ready.
* Retaining heap twice without freeing it. `/alloc` is cumulative, so two
calls that each fit can together exceed the heap and exit the JVM.
`/free` drops what is retained.
* Attendees sharing one project. Each attendee or pair needs their own
`java-vpa-<name>` project, or the single-replica demo pod gets fought over.

=== Recovering

If the sample pod is wedged, delete it; the Deployment recreates it in a few
seconds and the VPA admission controller sizes the replacement.
If the VPA status looks stale, delete and recreate the VPA; history resets but
it's a two-minute wait, not a session-ending one.
